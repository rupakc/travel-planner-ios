## 2. Navigation map

Router (App.jsx, react-router 6):
| Route | Screen | Auth |
|---|---|---|
| `/login` | LoginPage | public; `?next=` return path honoured (same-origin only) |
| `/share/:token` | SharePage (read-only trip card) | public |
| `/change-password` | ChangePasswordPage | RequireAuth (forced when `requires_password_change`) |
| `/` | Search tab (SearchPage, or ResultsPage once a search is running/finished) | RequireAuth |
| `/chat` | ChatPage | RequireAuth |
| `/alerts` | AlertsPage ("Watched prices") | RequireAuth (deep link `/alerts?kind=<kind>&watch=<id>`) |
| `/preferences` | PreferencesPage | RequireAuth |
| `/admin` | AdminPage | RequireAuth + `is_admin`, else redirect `/` |
| any other path | redirect to `/` | |

Notes:
- Web guard: unauthenticated users -> `/login?next=...`. NOTE: backend allows anonymous /search, /discover, single-agent routes (`get_optional_user`), but the web UI itself requires login for everything except share/login. Accounts are admin-created (no signup). JWT HS256 24h stored in localStorage `tp_token`; `Authorization: Bearer`.
- Search and Results are ONE tab: `hasSearchResults` toggles which is visible; both stay mounted (streaming never lost). Chat and Search tabs also stay mounted when switching. Results "New Search" (with confirm "Leave this page? Your search results will be lost." if search in progress) returns to the form.
- Top NavBar (sticky, h-14, white 85% blur): wordmark "Voyager" + segmented tabs `Search`, `Chat`, `Alerts` (sky unread dot), `Preferences`, (`Admin` if admin); right side: NotificationBell, username, purple "Admin" pill, Sign out icon. Mobile (<sm): hamburger "Menu" opens drawer list of the same tabs. Android equivalent: bottom nav of 4 (Search, Chat, Alerts, Preferences) + overflow for Admin/Sign out.
- Global overlays: FeedbackWidget (floating button, title "Give feedback"), AlertToast (bottom, aria-live), footer attribution (GeoNames CC BY 4.0, OurAirports), OnboardingTour.
- Cross-links: Recent search card -> loads into Search form; Chat can deep link `/?import=<url>` (opens From a link); Alerts card "Re-plan with this fare" -> sets search + goes to Search; notification click -> `/alerts?kind&watch`; Results "My Plan" FAB opens drawer; saved plan "View" -> PlanViewModal; share link -> `/share/<share_token>`.

## 4. Search form (SearchPage) fields and validation

Mode toggle (segmented, wraps): `I know where I'm going` | `Surprise me 🎲` | `Compare ⚖️` | `From a link ✨`. Modes: known, discover, compare, import.

### Mode "known" (default)
Above form: RecentSearches strip (collapsible "Recent searches" + count; horizontal snap list; each card shows route "A → B → C", dates, interest chips, traveller count; actions: tap = Load into form (notice teal: "Loaded {route}. Change anything you like, then plan." or if dates passed "…Its dates had passed, so they now start next week with the same trip length — check them, then plan."), re-run button (title "Run this exact search again" or, if past, "These dates have passed — load it and pick new dates"), remove X (aria "Remove recent search {route}"); passed dates labelled "· dates passed"; open/closed state in localStorage `tp_recent_searches_open`). Server keeps last 8 per user.
Fields (in order):
1. From (AirportSearch, placeholder "City or airport…", REQUIRED). Typeahead: min 2 chars, 300 ms debounce, `GET /api/airports/search?q=`, keyboard arrows.
2. To (AirportSearch, REQUIRED).
3. "+ Add stop" (multi-city; up to 3 intermediate stops): each "Stop N — on the way" (placeholder "Stopover city…", required) + "Nights (opt)" number 1-30 placeholder "auto"; route summary "Your route: Origin → stops → Dest". Payload `destinations` journey-ordered with final destination last; `destination_nights` same length (null last).
4. Departure (date, required, min=today). Defaults: departure = today+7d, return = today+14d.
5. Return (date, optional, min=departure; empty => one-way, sent as null via `apiReturnDate`).
6. Nationality (NationalitySearch, placeholder "American, Indian…", REQUIRED; `GET /api/nationalities/search`).
7. Budget (USD) number min 0 step 100, placeholder "Optional" (total trip budget; sent float or null).
8. Travelers panel (popover steppers): Adults 18–64, Seniors 65+, Children 5–17, Infants 0–4 (minus disabled at 0; adults can't drop so total <1); accessibility checkboxes: "♿ Wheelchair / Mobility aid" (wheelchair), "👁️ Visual impairment" (visual_impairment), "🦻 Hearing impairment" (hearing_impairment), "🧠 Cognitive / Neurodivergent" (cognitive_disability). Summary text "{N} traveler(s)" or chips. num_travelers = max(1, sum).
9. TagInput "🏠 Residence Permits (if any)" placeholder "Schengen, UK, UAE…"; TagInput "📋 Existing Visas (if any)" placeholder "US, Japan, Canada…".
10. "✨ Interests" toggle chips (multi): food 🍜, history 🏛️, adventure 🧗, culture 🎭, nature 🌿, shopping 🛍️, nightlife 🌙, wellness 🧘, art 🎨, family 👨‍👩‍👧 (selected = teal-600 fill, white text, 2px border).
11. "🎯 Discovery style" slider 0–1 step 0.05 default 0.5; live label `<0.33` "🏛️ Famous classics", `>0.66` "💎 Hidden gems", else "⚖️ Balanced mix"; end labels "Iconic must-sees" / "Off the beaten path"; aria-label "Serendipity dial: classics to hidden gems".
12. Submit "Plan My Trip" (search icon, teal gradient, full width).
Validation = HTML5 `required` + min dates only (no custom messages). Backend resolves origin/destination to IATA (`TravelSearchRequest`). Two-way binding: on submit nationality, permits, visas, interests, num_travelers, budget_category (<=1500 low, <=5000 medium, else high), adults/children/seniors/infants, accessibility_needs are PUT to /api/preferences; saved prefs pre-fill form (budget_category -> USD 1000/3000/8000). Recent search saved via POST /api/recent-searches.
Request body fields: origin, destination, departure_date, return_date, interests[], nationality, residence_permits[], existing_visas[], budget_usd, num_travelers, adults, children, seniors, infants, accessibility_needs[], serendipity, destinations[], destination_nights[], must_include/import_source (import), pace (remix).
